When several agents run in parallel from one session, each gets a scratch directory of its own, named for its task, and a destructive step in a scratch copy (planting a violation, deleting a folder) first checks that its target resolves inside that directory. Agents that share one scratch root and pick the same obvious names overwrite and delete each other's copies, and a planted violation meant for a copy can land in a real repository. Stops applying to a single agent. Costs one naming rule in the brief, and one path check before a destructive step.

## Evidence

In one meta-session, eight agents updating eight carriers in parallel each proved its audit changes by planting violations in a scratch copy. Two chose the same folder and script names in the shared scratch root and deleted each other's copies; afterwards the home repository's release folder was found with most of its generated files deleted and the exact planted violations of one agent's list, so one plant had run against the real tree instead of a copy. Nothing was committed damaged: the release was restored from its tag and every carrier's committed checksums matched the home's. Literature: none consulted; it is ordinary isolation of concurrent workers' temporary state.
