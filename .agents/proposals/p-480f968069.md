When a task is known to be complex, the session reads a catalogue of skills by role before it starts, and says in one line which it will use and which it skips. A task is complex on any of five signals: several decisions are open; it spans more than one area or repository; it needs more than about three steps, each committable alone; a failure's cause is unknown; or its work splits into independent parts. The catalogue extends *Skills from elsewhere* in `method/skills/README.md`: one row per role (brainstorming, `decision-review`, `user-walk`, writing a plan, executing a plan or driving subagents through it, dispatching parallel agents, test-first, systematic debugging, verification before completion, an isolated worktree, requesting and receiving a code review, finishing a branch, `close`), each with its signal and one example name from a public skill collection. A pointer goes where a session reads it at the start, since a rule acts only where the action reads it (`prompt-context.md` §*The enforcement ladder*); the README alone is never read. Each carrier's own `LOCAL` file lists which of the roles are installed there and under which name, so the catalogue never claims a skill the machine lacks. The skill trigger eval gains complex-task cases, where the expected first call is the catalogue or one of the skills it lists.

## Evidence

The owner asked for it on 2026-10-07 while the trigger eval's cases were drafted, and chose both places, the bundle and each carrier, and the concrete signals over the agent's own judgment. On the machine where it was asked, over a hundred general-purpose skills were installed, and the method's moment table names roles only, in a file no session reads at its start.
