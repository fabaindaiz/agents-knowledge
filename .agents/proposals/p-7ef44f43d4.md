# Proposal: propose-the-split-before-being-asked

A session that can divide work by disjoint file sets should propose the division itself, before the human has to ask whether parallel agents are possible. The proposal says why it is split, which model each piece gets, and what the whole costs against doing it in the main thread, and it names what cannot be split: anything that writes the same files, and anything the next step depends on. The expensive failure is not a bad split but a good one nobody offered, discovered only because the human asked.

## Evidence

One session. Three research tasks, then three bookkeeping tasks, then two reviews ran as parallel agents on disjoint file sets. Each batch was proposed only after the human asked whether parallelising was possible. The method already has a rule for agents on disjoint files and a recorded pilot item for parallelisation bounded to cost, so this adds only the duty to offer first. Note that the owner states a short-term objective on this very topic, so the occurrence may reflect that preference rather than a general need. Literature consulted: none.
