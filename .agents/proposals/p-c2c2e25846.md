A carrier's own audit does not re-check the bundle's internal shape (headers, note sections, index link forms, provenance markers); it calls `bundle.py verify`, which travels with the release and checks what the release promises, and keeps only the checks about the carrier's own use of the bundle. An audit that re-implements the release's structure is written against one release and turns red, or vacuous, on the next. The bootstrap's audit guidance says so.

## Evidence

Moving several carriers across one layout change, every carrier on the old layout had an audit that enforced it: between three and four hundred failures each on a correct release, none a real violation, and each audit had to be rewritten by hand in the same commit as the update.
