A tool that finds a section of a shipped document by its exact heading breaks silently when the heading is renamed: the lookup returns nothing, the tool falls back, and a test whose fixture repeats the old heading stays green. The key and the heading are two copies of one fact; a test must read the real document, not a fixture that copies the key.

## Evidence

On 2026-10-08 a method change renamed the session-log artifact's heading; the tool that reads the method's entry format from it by that heading stopped finding it, so a log without its own format would be refused and one with a format would lose fields the method added, with the whole suite passing, because the two tests that cover it built their fixture from the old heading. Found the same day while surveying what the tool reads by name; fixed with a test that reads the shipped document. Overlaps the stale derived copy: here the copy is a lookup key in code.
