Documentation drift is caught by a script rather than by review. A carrier keeps a map, read with the standard library, of each document agents load or follow to the globs it describes, each entry with a reason and whether it blocks or warns: the machine form of principle 16's prose map, which today is remembered rather than checked. A new `bundle.py docs-drift` has five modes. `--staged` warns at pre-commit. `--range BASE..HEAD` fails a blocking rule whose watched paths changed without its document, unless a commit in the range carries `docs-unchanged: <reason>`; it runs in a commit-message hook, in CI and in `close`, since the trailer does not exist before the message does. `--map`, inside `verify`, fails when a mapped document is missing or a glob matches nothing. `--refs`, inside `verify`, fails when a relative link or a backticked repository path in a mapped document does not exist. `--report --since 7d`, weekly, lists the rules triggered, the escapes with their reasons and rate per rule, the documents whose watched paths changed after their own last commit, and suggested pairs mined from history, never added by it. Renames count on both sides. Principle 16 points at the map and the command; `close` runs the range check and fixes only what it flags. Generated blocks with a check, a verified-at stamp and a budgeted model pass over listed documents wait until the first set proves itself.

## Evidence

Decided by the owner (d-5ed7e8-91f1be) after reporting generated documentation going stale in several carriers faster than it can be reviewed. Research in `meta/reviews/2026-10-07-doc-drift.md`: references to deleted code are common in public projects; two large projects run paired-block linters with a reason in the commit message as the escape; models alone flag nearly everything and are fit only for documents a cheap check flagged; escape hatches without a reason and a reported rate get silenced.
