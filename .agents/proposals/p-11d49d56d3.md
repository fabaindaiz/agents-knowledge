# Proposal: two-checks-of-one-tool-can-contradict

When one tool owns two checks, each correct against its own tests, the place where their inputs overlap is covered by neither. A waiver for a content check is documented as "on that line"; a record format is checked by counting the columns of a table row. Written at the end of such a row, the waiver adds a column and fails the column check; written inside the last cell it passes, but only if nothing quoted in code style follows it, because the waiver's pattern stops at that quote character. Each rule worked alone; the contradiction surfaced only when a real record needed both. The method should ask that a documented placement for an escape hatch be exercised once against every record format the same tool validates, and that the first such collision be written down where the placement is documented, with the working placement.

## Evidence

One session, one repository of the kind that keeps an append-only decisions log as a five-column table beside a privacy check with an in-place waiver. Both failures happened within the same session: first the extra column, then the waiver not being read when a code-quoted span followed it. The working placement, inside the last cell with nothing quoted after it, was found by trial and recorded in a roadmap item that also asks for the rules to be fixed. The same item counts six privacy false positives over two sessions, so the waiver was in regular use when the collision appeared. Literature consulted: none.
