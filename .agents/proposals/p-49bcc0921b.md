# Proposal: superlinear-cost-in-a-cheap-looking-step

A loop that reads as linear is quadratic when each pass calls something linear in the whole input (a library routine that measures the remaining buffer, a membership test that scans an array), and a pattern match that reads as cheap is exponential in a backtracking engine on some patterns an automaton runs in linear time. The usual answer, "this step is cheap", is wrong exactly where the input grows. It stops applying at small, bounded inputs, and for patterns with backreferences, which need backtracking. The check: time the step at n and at 2n (a sampling profiler names the call when time more than doubles), and feed a pattern pathological input of growing length; switching to a linear-time engine costs features.

## Evidence

A public write-up of a game's loading time found both forms in one parse of a large document and cut the load by about two thirds (2021). Cox, *Regular Expression Matching Can Be Simple And Fast* (2007): a backtracking engine took tens of seconds where a Thompson automaton took microseconds at small n.
