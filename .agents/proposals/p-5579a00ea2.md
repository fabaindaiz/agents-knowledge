# Proposal: choose-the-algorithm-by-n-and-input-shape

For the common tasks the textbook choice depends on the size and the shape of the input, and the usual answer is wrong at one end: a sorted array with a branch-free binary search beats a tree or hash for a static table at small n, while a heap-ordered layout wins at large n; a heap for top-k wins only when k is small against n, a full sort for larger k, min or max for one; current library sorts detect runs and equal keys, so the quadratic quicksort worry is outdated, but they are not stable. It stops applying where the structure is updated often or the full order is needed anyway. The check: benchmark on the real input shape (random, nearly sorted, many duplicates) across sizes, looking for the crossover where the working set leaves the cache; never hand-roll a sort.

## Evidence

Khuong, Morin, *Array Layouts for Comparison-Based Searching* (arXiv 1509.05053); a standard library's heap-module documentation on when its top-k functions beat a sort; Peters, *Pattern-defeating Quicksort* (arXiv 2106.05123).
