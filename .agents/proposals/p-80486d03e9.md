A plan carries a status table (task, state, commit) updated as each task lands, with the commit's hash; a task found wrong is marked with its reason rather than dropped. A session resuming the work reads the table first; one rebuilt at the end describes what someone remembers, not what happened.

## Evidence

The implementation procedure several carriers share requires one commit per task and the table kept current as each lands; the method's plan guidance has no such table, and its resume path relies on the change log and the roadmap.
