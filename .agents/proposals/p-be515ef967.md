A meta-session should read each carrier's current integration branch, not the bundle branch the last meta-session left: carriers merge the bundle branch into their integration branch by pull request and delete it on the remote, so the local bundle branch goes stale while the remote one is gone. The pre-flight should ask, per carrier, which branch the update starts from and how it lands (a ticket branch and a pull request, or a direct commit), from the carrier's own rules read first.

## Evidence

In the meta-session of 2026-10-05, three priority carriers' bundle branches had been merged into their integration branches and deleted on the remote; their local copies were behind, and the agreed plan, to commit on the bundle branch, had no target. Each update went on a new branch cut from the integration branch, for a pull request.
