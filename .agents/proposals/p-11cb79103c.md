A carrier's `LOCAL.md` that replaces a whole `##` section of a method skill silently drops every later change the bundle makes to that section: an update installs, `install-skills --check` passes, and the new rule never reaches the carrier. The same holds for a replaced `description`, which 0.0.28 already answers with the when-to-use key. The install should name, for each replaced section, whether the base's version of it changed since the carrier's last install, so the carrier re-reads it.

## Evidence

In one carrier, `close`'s `LOCAL.md` replaced the base's section 0; 0.0.27 added a paragraph there (offer the close before a push that ends a plan), and it was absent from the installed skill until the carrier's agent noticed and copied it by hand. Another carrier's phrases had replaced `description` the same way and were moved to the when-to-use key at 0.0.28.
