# Proposal: an-access-path-is-read-in-the-plan

How data is reached is decided by the engine's plan, not by the schema, and three usual answers are wrong there: an index is not free, since in a versioned-row store an update touching no indexed column skips index upkeep and a new index on an updated column ends that; equality-first composite index order holds, but engines with skip scan no longer rule an index out for a missing leading column, so the rule is version-dependent; offset pagination reads and discards every skipped row and duplicates or drops rows on concurrent inserts, where keyset pagination stays flat. Heavy block compression of analytic columns is likewise not free against decode speed. It stops applying on read-mostly tables, small bounded tables and cold storage. The check: read the plan (index condition against filter, rows removed, buffers) and the engine's update and index-use counters, on the target engine version, before and after.

## Evidence

A relational engine's documentation on heap-only tuples and on multicolumn indexes; *No Offset*, an index-tuning site; Zeng et al., *An Empirical Evaluation of Columnar Storage Formats* (arXiv 2304.05028), abstract.
