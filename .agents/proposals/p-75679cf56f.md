# Proposal: cite-or-read-before-asserting

The assertion most likely to be made from memory is a short identifier — a slug, a record id, a flag name, a
file name — because it is small enough to feel remembered and too small to look wrong when written down. A
sentence invented from memory reads as a guess and invites a check; an identifier invented from memory reads as
a citation and closes the question. So the rule that a statement is cited by file and line or read before it is
made has a sharper form for identifiers: an identifier written into a record is resolved against the thing it
names, at the moment it is written, and the resolution is mechanical rather than remembered. The useful part is
that this is nearly always checkable by code, because an identifier that names something in the repository can
be looked up: a note slug resolves to a file, a record id to its defining row, a flag to the parser that accepts
it.

## Evidence

One occurrence in one owner's repositories on 2026-11-24, counted as one source: two note slugs were written
into a tracking table as admitted at the release being cut. Both were plausible in form and in subject, and
neither existed — one named a decision-review behaviour and the other a branch-review rule, both real subjects
of that session, neither a real note. They were found by a later search of the notes folder, not by any check,
and the table they were in is the record the next release reads to know what was admitted, so an invented slug
there would have been carried forward as fact. The same session had, minutes earlier, written into its own
guidance the principle that a statement about the code or about a past event is cited or read before it is made.
No measurement: what would settle the general claim is a count, over a set of records, of how many cited
identifiers resolve. What is immediately available instead is the mechanical check, which the carrier that found
this is in a position to write and run over its own tracking tables. Literature: none consulted for this
extension; the parent candidate carries the general case.
