# Proposal: no-foreign-shell-constructs

An agent whose shell is zsh, writing the POSIX habit of an unquoted variable holding a list of paths, passes the whole list as one argument: zsh does not split words on unquoted expansion. The command does not fail loudly; a tool given one long path that names nothing reports "no bundle" or does nothing, and the agent reads that as a fact about the repositories. The zsh-native fix (a parameter-expansion flag) can then be refused by a host's safety check that cannot parse it. Passing the list from a small program to a subprocess as an argument vector avoids both.

## Evidence

One session of the home, on a machine whose agent shell is zsh: twice the same construct broke a command over many repositories, once in a count and once in a write over sixteen carriers, where the write tool reported every carrier but one as missing. The zsh-native rewrite was refused by the host's guard as unparseable; the same list passed from a program's argument vector ran at once. The method already holds the rule against foreign shell constructs; this is the case where the construct is the agent's own default, not a pasted one. One repository, one owner.
