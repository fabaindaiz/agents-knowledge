# Documentation drift, caught by a script

**Date:** 2026-10-07. **Status:** research by a delegated agent, read-only; shapes `d-5ed7e8-91f1be` and its
proposal. Sources are ideas only, paraphrased; ASSUMPTION marks a claim read only through a summary.

## How common it is

- In thousands of public projects, most held at some point a reference in their documentation to code that had been
  deleted. Over a quarter of the most popular did at the time of a follow-up, whose authors published a check that
  runs on each change.
- Comments inconsistent with the code made a change about one and a half times likelier to introduce a bug, most
  right after the inconsistency appeared.
- Agent context files change like configuration code, through frequent small additions. Over their lifetime they
  more than tripled in size, because deleting a rule feels risky. A one-line reason beside each rule cut that growth.
- Out-of-date content is a top-level category of documentation problems.

## Practice

- **Paired blocks.** Two large public projects mark a block of code and the file it must change with. A linter fails
  when one side changes without the other, escaped by a reason in the commit message. One of them only warns and asks
  for links both ways.
- **Code-coupled documentation services** check on every commit and fail CI on larger drifts (the rule is proprietary).
- **Generated blocks** inside documents are regenerated, and a `--check` fails when one is stale.
- **Regenerating only what changed** documents only changed objects and their direct dependants, from a pre-commit
  hook.
- **Mining history**: what changed together in the past suggests couplings code analysis cannot see (ASSUMPTION
  for the figures).
- **Language models alone** flag nearly everything as inconsistent. Filtered, or compared against generated tests,
  they reach moderate precision and lower recall. So a model runs only on documents a cheap check already flagged,
  and never as the gate.
- **Escape hatches**: a warning treated as a box to clear gets silenced, and a tool whose warnings are not acted on
  stops being used. The escape rate per rule is therefore worth reporting.

## Gaps in the decided design, most serious first

1. **Touched is not true.** The co-change rule proves only that the document was edited; a typo fix satisfies it.
   *Mitigation:* turn checkable facts into assertions (generated blocks, commands with expected output), and check
   references.
2. **Documents about behaviour, conventions or outside systems watch no path.** *Later:* a stamp of the commit a
   document was verified at, with a report of the documents whose dependencies changed since.
3. **Escape abuse and fatigue.** *Mitigation:* a reason required, narrow rules block and broad ones warn, and a
   report of each rule's escape rate; a rule escaped most of the time is narrowed or deleted.
4. **The escape cannot be read before the commit message exists.** *So:* the trailer is checked in a commit-message
   hook, in CI or at close over a range of commits; the pre-commit check only warns.
5. **The map goes stale.** *Mitigation:* the map is verified (every document exists, every glob matches a file), and
   renames count on both sides of the diff.
6. **The map grows.** *Mitigation:* map only documents agents load or follow, a mandatory reason per rule, and history
   mining that suggests rules but never adds them.
7. **File-level rules are coarse.** Section anchors can come later.

## The minimal set it recommends

A carrier-owned map read with the standard library, each entry a document, the globs it watches, a reason, and
whether it blocks or warns: the machine form of principle 16's prose map. Then five modes:

- `--staged` warns at pre-commit;
- `--range BASE..HEAD` fails a blocking rule unless a commit in the range carries `docs-unchanged: <reason>`, for
  the commit-message hook, CI and `close`;
- `--map` inside `verify` checks the map itself;
- `--refs` inside `verify` checks that relative links and backticked repository paths in mapped documents exist;
- `--report --since 7d` runs weekly: rules triggered, escapes with their reasons and rate, documents whose watched
  paths changed after the document's last commit, and suggested pairs from history.

Generated blocks, a verified-at stamp and a budgeted model pass over listed documents only come later, if the first
set proves itself. The cost is a diff, glob matching and a search, with no model.
