# Carrying 0.0.30 to the carriers (2026-10-08)

Phase 2 of release 0.0.30, run from the home on the owner's request:
- **Target:** every carrier open on this machine, except one the owner carries by hand.
- **Deliverable:** one new branch per carrier, ready to merge into that repository's development branch.
- **Write-up:** the process, and every learning, for the next release or a fix.

Carriers are counted here, never named. Which is which lives in this machine's manifest.

## Scope and estimate

| | |
|---|---|
| Carriers carried | 10: four personal (small, one owner) and six work repositories |
| Left out | the one the owner carries by hand; one repository with no bundle (not a carrier) |
| Estimate given before starting | pre-carry review ~15 min at a small cost (units, in order of magnitude); carrying ~2 h at about 1e6 main-model tokens; this write-up ~20 min |
| What it took | the review ran in under 3 minutes of wall time (10 agents in parallel, about 0.8e6 tokens between them); the carrying took about 2 h, as estimated |

## The process as run

1. **Pre-carry review.** One read-only mid-size-model agent per carrier.
   - **Read:** its rules (development branch, landing, branch names, commit format), its state (checked-out branch,
     uncommitted work, an unmerged branch from the last carry), its gate and audit, references 0.0.30 breaks, its
     session log, its root-file lines, every meeting point between 0.0.30 and its own procedures, and its Cursor and
     Copilot files.
   - **Report:** each wrote to a scratch file outside every repository.
2. **Per carrier, in a git worktree** in one scratch folder, so no owner's checkout was switched:
   - a new branch `chore/agent-guides-0.0.30` from the base the rules below pick;
   - `release.py splice --write --backup`;
   - `install-skills`, unless the carrier declined the skills;
   - the agents copied again;
   - the fourth Phase 4 line added in the repository's language;
   - `log` set in `carrier.toml` where the log is not at the default path;
   - `proposals --prune`;
   - `verify`, the carrier's audit and the rest of its gate;
   - a changelog entry in its format;
   - one commit in its style, with no push.
3. **Phase 3.** `release.py register` and `align` on the worktree paths. Nine aligned. `register` recorded the
   repositories' own paths, never the scratch ones. Then the worktrees were removed so that the owner can check out
   the branches; the branches stay.

**How the base branch was picked**, a rule worth writing into `prompt-sync.md`:

| Situation | Base | Seen in |
|---|---|---|
| An unmerged branch from the last carry, holding host adaptations beyond `.agents/` | that branch: merging the new one brings both | 4 |
| The development branch lacks `.agents/` and the last carry lives on an unmerged branch | that branch | 1 |
| The local default branch predates a history rewrite (diverged, no merge base) | the remote one | 2 |
| The local default branch is ahead of the remote with the owner's unpushed work | the local one, which contains the remote | 1 |
| Otherwise | the remote development branch | 2 |

## What it found

### Defects of release 0.0.30, for the home to fix

1. **A product noun in a lookup cue.**
   - **What:** one note's `cues`, new in 0.0.30, name a document store's product.
   - **Why it is a defect:** the bundle names no product.
   - **Who caught it:** one carrier's host-noun audit. The home's privacy check did not, since a public product is
     not a private term.
   - **Fix:** say the cue by mechanism, and scan the cues for product nouns in the build. That carrier's branch waits
     on it.
2. **Layout changes a carrier's audit reads, not flagged.**
   - **What changed:** 0.0.30 removed `knowledge/areas/`, wrote the index's *By phase of work* cards as code spans
     instead of links, and moved the topics into a table.
   - **What broke:** six carriers' audits re-check that layout, and all six failed on the carry, between 51 and 154
     findings each.
   - **The miss:** the changelog listed the cuts, but not as layout changes. And `prompt-sync.md`'s step to "run
     each carrier's own audit over the new release in a scratch copy" was not run before the cut.
   - **Fix:** a changelog heading for layout changes; that step made a precondition of the cut; and
     `i-5ed7e8-307d02`, below.
3. **`prompt-update.md` step 3b names three Phase 4 lines, not the fourth** that 0.0.30 added. All ten carriers lacked
   it.

### Tool defects

4. **`bundle.py new entry` fails on a log in another language.**
   - **Format misread:** a log whose format lists its labels on one line separated by ` / ` is read as a single
     field.
   - **Fields duplicated:** the method's fields are matched by their English label, so all twelve are appended in
     English.
   - **Fix:** parse the separated labels, and do not append the method's fields to a log that states its own format
     in another language.
5. **`install-skills` ignores `declined`.** In one carrier that declined the skills, it installed three, and they
   were removed by hand. It should skip a skill a `declined` entry names, or at least warn.

### Process learnings

6. **Worktrees side by side.** A carrier whose documents point at a sibling repository fails its document-map check
   in a scratch worktree unless the sibling's worktree sits beside it. Name worktrees after their repositories, in
   one folder.
7. **A worktree's gate needs the main checkout's environment.** Gates that need a project environment ran in the
   worktree with the main checkout's (`hatch env find`), never by installing. A gate that builds toolchains from
   scratch is reported as not run, with what ran instead.
8. **No `git stash` in a carrier's worktree.** The stash is shared by every worktree of a repository. Compare with
   `git show HEAD:path`.
9. **Never type a record id by hand.** One entry first took a test fixture's prefix; take it from `bundle.py id` or
   `new entry`.
10. **Conflicting branch rules.** Two personal carriers commit straight to the default branch and two work carriers
    name branches by a ticket key. The owner's request for a branch wins and is said in the entry; the name is the
    owner's to change.
11. **The `log` field was missing** in six carriers whose log is not at the default path. The update could set it
    from `adapted`, or ask.
12. **The ledger disagreed with two carriers.** It recorded them at 0.0.28 while their release read 0.0.25,
    presumably a registration from the other machine.
13. **Re-checks of the release's internals.** Six carrier audits re-check the release's layout, which `bundle.py
    verify` owns, and two share one lineage of that code. Their own docstrings say to adapt the audit, not the
    release, when verify passes. Each release that moves the layout costs every such carrier a code change
    (`i-5ed7e8-307d02`).
